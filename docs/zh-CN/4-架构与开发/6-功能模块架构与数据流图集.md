# 功能模块架构与数据流图集

> 本图集按功能拆分可维护的 Mermaid 源码。图中只保留稳定边界；实现变化时，应同时更新“维护说明”和源码锚点，而不是把所有内部函数塞进一张巨图。

## 1. 聊天与会话

**用途与边界**：Renderer 管理消息 UI、每会话 Agent loop 和流状态；Rust 规范化 provider 请求、解析流并持久化模型交换。

```mermaid
flowchart LR
    input["Chat input"] --> loop["Renderer useAgentLoop"]
    loop --> preload["Preload createResponseStream"]
    preload --> ipc["Main chatHandlers"]
    ipc --> stream["Rust conversation stream"]
    stream --> provider["Chat Responses Anthropic Gemini Interactions"]
    provider --> db["chat_conversations chat_messages usage_records"]
    stream -. "streamId chunks" .-> loop
    loop --> view["Message rendering and run metrics"]
```

**Agent 迭代与状态感知数据流**：

```mermaid
flowchart TD
    UserMsg["用户输入 / Steering 追问"] --> AgentLoop["useAgentLoop 迭代调度"]
    AgentLoop --> StreamReq["createResponseStream (IPC / Rust)"]
    StreamReq --> Model["Provider (Chat / Responses / Anthropic / Gemini / Interactions)"]
    Model -. "SSE Chunks (带 StreamRetryNotice 重试提示)" .-> AgentLoop
    Model --> ResSettled["响应结算: 解析 toolCalls"]
    ResSettled -- "无工具调用" --> SteeringCheck{"是否有中途待消费 Steering?"}
    SteeringCheck -- 是 --> AgentLoop
    SteeringCheck -- 否 --> TaskDone["finishAgentTask 结束运行"]

    ResSettled -- "包含工具调用" --> Guard["ReadonlyCallGuard"]
    Guard --> Probe{"物理文件与 Git 状态探针检测"}
    Probe -- "已变更 / 首次调用" --> Auth["工具授权 (YOLO / 用户确认)"]
    Probe -- "完全无变动重复读取" --> Dedupe["隔离拦截, 返回友好去重提示"]
    Auth --> Exec["工具执行 (MCP / 终端 / 子代理 / LSP)"]
    Exec --> CacheUpdate["Guard 快照更新 (写操作失效缓存 / 读操作记录快照)"]
    Dedupe --> LoopNext["追加 toolResultMessage"]
    CacheUpdate --> LoopNext
    LoopNext --> AgentLoop
```

**维护说明**：不要把 `sessionProxy.ts` 画进 AI 流；工具结果由 Renderer 生成 `toolResultsJson` 后进入下一模型轮次。只读工具经由 `ReadonlyCallGuard` 结合 Git 状态和文件物理指纹进行主动变动感知。

**源码锚点**：`src/renderer/components/mainContent/chatMessages/hooks/useAgentLoop.ts`、`src/renderer/components/mainContent/chatMessages/hooks/readonlyCallGuard.ts`、`src/preload/modules/apiConfigApi.ts`、`src/main/ipc/handlers/chatHandlers.ts`、`native/src/api/conversation/stream.rs`、`native/src/api/interactions/`、`native/src/storage/services/chat_conversations.rs`。

## 2. MCP 工具发现与调用

**用途与边界**：Rust 生成模型可见工具集合并执行工具；Renderer 负责用户授权和调用轮次，不负责绕过 Rust 策略。

```mermaid
flowchart TD
    request["Model request scope"] --> discover["collect_all_mcp_tools"]
    builtin["14 fixed-order built-in services"] --> discover
    skills["Dynamic Skills tool"] --> discover
    external["External MCP stdio and HTTP discovery"] --> discover
    flags["Project enablement codebase index imagegen config"] --> discover
    discover --> model["Provider-specific tool JSON"]
    model --> callNode["call_mcp_tool"]
    callNode --> policy["Sub-agent and authorization checks"]
    policy --> route["Built-in remote external or special route"]
    route --> mask["Privacy-masked result"]
```

**维护说明**：固定服务必须追加到 `builtin_services_in_order` 末尾以保持 prompt cache；Skills 和 remote workspace 不计入 14 个固定服务。

**源码锚点**：`native/src/mcp/builtin.rs`、`native/src/mcp/tools.rs`、`native/src/mcp/service.rs`、`native/src/mcp/external/`、`native/src/mcp/privacy_mask.rs`。

## 3. Skills

**用途与边界**：Skills 配置按全局或项目 scope 管理，模型侧工具按请求动态注入；内置 Skills 和文档在启动时幂等同步到 `~/.snow/`。

```mermaid
flowchart LR
    startup["Main bootstrap"] --> sync["ensureBuiltinSkills and docs"]
    sync --> home["~/.snow skills and docs"]
    config["config service skills scope"] --> store["SkillsConfigService"]
    project["Active project scope"] --> tool["SkillsService dynamic tool"]
    home --> tool
    store --> tool
    tool --> prompt["Model-visible skill executor"]
    prompt --> load["Load selected skill instructions"]
```

**维护说明**：`skills_config` 是 config 的 skills scope 委托，不是独立注册 MCP 服务；动态工具是否出现取决于 scope 和可用配置。

**源码锚点**：`src/main/app/ensureBuiltinSkills.ts`、`native/src/mcp/servers/skills.rs`、`native/src/mcp/servers/skills_config.rs`、`native/src/mcp/servers/config.rs`、`native/src/mcp/tools.rs`。

## 4. Hooks 与子代理

**用途与边界**：Hooks 为用户消息、工具、压缩和子代理生命周期提供可配置决策点；子代理是独立会话和 Renderer loop，但权限及 checkpoint 受父会话约束。

```mermaid
sequenceDiagram
    participant P as Parent agent loop
    participant H as Hooks
    participant S as Sub-agent service
    participant C as Child renderer loop
    participant DB as SQLite

    P->>H: beforeSubAgentStart
    H-->>P: pass or abort
    P->>S: activate configured agent
    S->>DB: accept durable run, create child conversation
    S->>C: start with profile tools and parent checkpoints
    loop Child model and tools
        C->>C: independent stream and allowed-tools checks
    end
    C->>DB: settle terminal state, async also writes the run event
    C->>H: onSubAgentComplete
    C-->>P: sync mode returns the unified result
    DB-->>P: async mode delivers the event and wakes the parent
```

**维护说明**：工具 Hook 顺序是 `toolConfirmation` → 授权 → `beforeToolCall` → MCP → `afterToolCall`。父 abort 传播到子代理；启动时把遗留非终态运行置为 `interrupted`，不自动重放。异步模式的结果投递与父会话唤醒见 [Agent 运行时与工具编排](4-Agent运行时与工具编排.md) §9.4。

**源码锚点**：`src/renderer/components/mainContent/chatMessages/hooks/subAgentActivation.ts`、`subAgentParentInbox.ts`、`subAgentRunRegistry.ts`、`toolExecution.ts`、`useToolAuthorization.ts`、`hookOutcome.ts`、`native/src/hooks/`、`native/src/mcp/servers/sub_agents.rs`、`native/src/storage/services/chat_conversations/sub_agent_runs.rs`。

## 5. 图像生成与图库

**用途与边界**：imagegen MCP 依据独立 channel 配置调用 provider；生成结果写文件并登记图库，Renderer 将连续并行调用合并为画廊。

```mermaid
flowchart TD
    model["Agent tool calls"] --> executor["Renderer tool executor"]
    executor --> imagegen["Rust imagegen MCP service"]
    channels["Enabled image generation channels"] --> imagegen
    imagegen --> provider["OpenAI-compatible or Gemini backend"]
    provider --> files["Image files under default or custom root"]
    files --> index["image_library SQLite index"]
    index --> ipc["Image library IPC"]
    ipc --> ui["Library UI and chat image references"]
    executor --> gallery["ImageGenGallery for consecutive parallel calls"]
```

**维护说明**：工具只在至少一个 channel 启用时发现。并行多图是多次工具调用，Renderer 画廊负责统一网格；图库目录更换走 prepare/chunk/commit/rollback journal 流程。

**源码锚点**：`native/src/mcp/servers/imagegen.rs`、`src/main/ipc/handlers/imageHandlers.ts`、`native/src/storage/services/image_library.rs`、`native/src/exports/images.rs`、`src/main/ipc/handlers/imageLibraryHandlers.ts`。

## 6. 浏览器

**用途与边界**：Renderer webview 提供可视页面，Main 管理 Electron 网络记录、弹窗、密码和上下文菜单，Rust MCP browser 服务暴露模型工具。

```mermaid
flowchart LR
    agent["Browser MCP calls"] --> rust["native browser service"]
    rust --> main["Main browser support"]
    ui["Renderer browser panel and webview"] --> main
    main --> webview["Electron webview session"]
    webview --> network["Network recorder and trace"]
    webview --> dialogs["JS dialogs and popup windows"]
    webview --> storage["Cookies storage state passwords"]
    proxy["Electron session proxy"] --> webview
```

**维护说明**：`browserNetworkRecorder`、storage state 和 trace 是辅助模块，不是独立 IPC 注册组。OAuth popup 需要保留 `window.opener` 关系；网络代理由 `sessionProxy.ts` 应用到 Electron session。

**源码锚点**：`native/src/mcp/servers/browser.rs`、`src/main/ipc/handlers/browserNetworkRecorder.ts`、`browserStorageState.ts`、`browserTrace.ts`、`browserPasswordHandlers.ts`、`src/main/browser/browserPopupWindow.ts`、`src/main/app/sessionProxy.ts`。

## 7. 终端与 SSH

**用途与边界**：本地 PTY 和持久 terminal 工具由本地进程管理；SSH manager、远程命令和 remote workspace 适配远端文件、命令与 Git。

```mermaid
flowchart TD
    ui["Terminal and SSH UI"] --> preload["ptyApi and sshApi"]
    preload --> main["PTY handlers and SSH handlers"]
    main --> local["Local PTY sessions"]
    main --> ssh["SSH manager and credential resolution"]
    ssh --> remote["Remote command workspace and Git"]
    agent["bash filesystem grep terminal tools"] --> tools["Rust MCP routing"]
    tools --> local
    tools --> remote
    remote --> execution["Cancellable remote execution ID"]
```

**维护说明**：terminal MCP 默认禁用，需项目显式开启。远程 workspace 是执行支撑，不应重复注册为固定内置服务；Windows/本地与 SSH 路径解析必须在路由前完成。

**源码锚点**：`src/main/pty/registerPtyHandlers.ts`、`src/main/ipc/handlers/sshHandlers.ts`、`src/main/ssh/sshManager.ts`、`remoteWorkspaceCommand.ts`、`remoteGit.ts`、`native/src/mcp/servers/terminal.rs`、`remote_workspace.rs`。

## 8. Git 与代码库索引

**用途与边界**：UI Git 经 Main 和 native export 调用本地或远程 Git；代码库索引由 Rust 构建 embedding/chunk，并仅在索引可用时向模型暴露搜索工具。

```mermaid
flowchart LR
    gitui["Git UI"] --> gitipc["gitHandlers"]
    gitipc --> localgit["native git export"]
    gitipc --> remotegit["SSH remoteGit"]
    workspace["Workspace source files"] --> index["Rust codebase indexing"]
    index --> chunks["Vector chunks and embed sessions"]
    chunks --> search["codebase MCP tools"]
    search --> agent["Agent context"]
```

**维护说明**：Git UI 操作与模型工具授权是不同入口。codebase 工具要求有效 project、项目启用且已有 chunk；未建索引时应隐藏而不是返回空能力。

**源码锚点**：`src/main/ipc/handlers/gitHandlers.ts`、`src/main/ssh/remoteGit.ts`、`native/src/exports/git.rs`、`native/src/exports/codebase.rs`、`native/src/mcp/servers/codebase.rs`、`native/src/storage/services/codebase_embed_sessions.rs`。

## 9. Git 工作树与会话执行域隔离

**用途与边界**：支持同一个 Git 仓库在多个分支或独立隔离工作树（WorkTree）下并行开启对话；前端选择器绑定会话执行域，底层通过 SQLite 写锁保证并发安全，请求契约将 `executionWorkspaceRoot` 和 `worktreeId` 严格透传给工具与文件快照 Checkpoint。

```mermaid
flowchart TD
    UI["WorktreeSessionSelector (UI)"] --> BindIPC["git:worktrees:set-conversation"]
    BindIPC --> RustStorage["native worktrees.rs 存储服务"]
    RustStorage --> WriteLock["with_write_lock & with_write_retry"]
    WriteLock --> DB[("SQLite conversations 表")]

    AgentRun["useAgentLoop 发起请求"] --> PathResolver["resolveConversationWorkspacePath"]
    PathResolver --> RequestContract["Request Payload:\nexecutionWorkspaceRoot & worktreeId"]
    RequestContract --> NativeStream["native create_response_stream"]
    NativeStream --> ToolContext["MCP 工具路由 & Checkpoint 目录绑定"]
    ToolContext --> IsolatedDir["独立工作树物理根目录 (如 /modules/tasks)"]
```

**维护说明**：处于工作树模式时，系统提示词中的工作目录必须严格对齐 `executionWorkspaceRoot`，底层文件变更面板与 Checkpoint 回滚目录（`manifest.work_dir`）必须与物理执行目录保持 100% 对称。

**源码锚点**：`native/src/storage/services/git/worktrees.rs`、`src/renderer/components/mainContent/chatInput/WorktreeSessionSelector.tsx`、`src/renderer/components/mainContent/chatMessages/utils/conversationHelpers.ts`、`src/main/ipc/handlers/gitHandlers.ts`。

flowchart TD
    ui["Settings UI"] --> api["Preload config API"]

## 11. 应用更新

**用途与边界**：更新器按平台分支；非 macOS 使用 electron-updater 的显式下载/安装状态机，macOS 使用独立检查与下载实现。更新网络遵循 updater 专用 Electron session 代理。

```mermaid
stateDiagram-v2
    [*] --> Checking
    Checking --> NotAvailable: no update
    Checking --> Available: update found
    Checking --> Failed: check error
    Available --> Downloading: user starts download
    Downloading --> Downloaded: package ready
    Downloading --> Failed: download error
    Downloaded --> Installing: user confirms install
    Installing --> [*]
    NotAvailable --> [*]
    Failed --> [*]
```

**维护说明**：非 macOS 禁止自动下载和退出自动安装；状态必须体现用户触发的下载与安装。macOS 下载缓存位于 userData updates 相关目录。default session 与 updater partition 都通过 `applySessionProxy`。

**源码锚点**：`src/main/updater/autoUpdater.ts`、`electronUpdater.ts`、`macUpdater.ts`、`updateStatus.ts`、`src/main/app/mainWindow.ts`、`src/main/app/sessionProxy.ts`。

## 12. LSP 语言服务器与语义代码分析

**用途与边界**：提供多语言服务器（Rust `rust-analyzer`、TypeScript `typescript-language-server`、Go `gopls` 等）的进程生命周期管理、语义定义跳转、悬停文档、引用查找与批处理诊断；推送式诊断通过本地缓存向前端和模型提供亚毫秒级响应。

```mermaid
flowchart LR
    AgentTools["Agent LSP 工具\n(goto / hover / references / symbols)"] --> LspServer["mcp/servers/lsp/"]
    LspServer --> ClientMgr["LspClient 进程管理器"]
    ClientMgr --> Subprocess["Language Server 独立进程\n(rust-analyzer / node / gopls)"]
    Subprocess -. "JSON-RPC (stdio)" .-> ClientMgr
    Subprocess -. "textDocument/publishDiagnostics" .-> PushCache["Push Diagnostic Cache\n(推模式诊断缓存)"]
    PushCache --> DiagTools["lsp-diagnostics / workspace-diagnostics"]
    DiagTools --> AgentContext["模型上下文反馈 & 质量复核"]
```

**维护说明**：LSP 工具按能力和语言动态注册；若语言服务器处于退避冷却期或未安装，对应 `lsp-*` 工具不可见，改用字面检索。诊断工具必须使用 `filePaths` 数组入参。

**源码锚点**：`native/src/mcp/servers/lsp/`、`native/src/mcp/servers/lsp/client.rs`、`native/src/mcp/servers/lsp/prompt_context.rs`、`src/renderer/components/mainContent/chatInput/LspStatusBadge.tsx`。

## 13. 定时任务与可视化工作流编排

**用途与边界**：定时任务提供无头 Agent 自动执行与 Cron/间隔调度；可视化工作流（Workflow Engine）将复杂任务分解为有向无环图（DAG），支持用户在 UI 上交互审核节点、单步继续或在失败节点上续跑。

```mermaid
flowchart TD
    ScheduleTimer["渲染进程定时调度器 (Cron / Interval)"] --> TaskRun["config-manage action=set scope=scheduledTasks"]
    TaskRun --> TaskStore[("SQLite scheduled_tasks 表")]
    TaskRun --> HookTrigger["Lifecycle Hook (onSessionStart)"]
    HookTrigger --> HeadlessLoop["无头模式 useAgentLoop 自动会话"]

    WorkflowCall["模型调用 workflow-generate\n(输出 DAG 节点图 JSON)"] --> WFRunner["WorkflowRunner (workflowRunner.ts)"]
    WFRunner --> DAGCheck["parseWorkflowGraph 校验依赖关系"]
    DAGCheck --> UINotify["UI 节点图渲染 & 用户交互确认"]
    UINotify --> NodeExec["调度子代理与工具逐节点执行"]
    NodeExec --> NodeStatus{"节点执行是否成功?"}
    NodeStatus -- 成功 --> NextNodes["解锁后续依赖节点继续执行"]
    NodeStatus -- 失败 --> PauseFlow["暂停工作流，等待用户修改或 workflow-resume 续跑"]
```

**维护说明**：定时任务在渲染进程常驻计时器中驱动，但在数据库中做全量历史落库与执行次数统计；工作流节点图解析必须防范环形依赖，失败恢复通过 `workflow-resume` 串联原上下文。

**源码锚点**：`src/renderer/components/mainContent/chatMessages/workflow/workflowRunner.ts`、`src/renderer/components/mainContent/chatMessages/toolCalls/WorkflowToolCall.tsx`、`src/preload/modules/scheduledTaskApi.ts`、`native/src/storage/services/scheduled_tasks.rs`。
